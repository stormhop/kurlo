# Changelog

All notable changes to Kurlo are documented here. This project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [Unreleased]

### Added

- **OAuth 1.0 auth.** The Auth tab signs requests with OAuth 1.0a: consumer key and secret, access token and token secret, `HMAC-SHA1`, `HMAC-SHA256`, `HMAC-SHA512`, `RSA-SHA1`, `RSA-SHA256`, `RSA-SHA512` or `PLAINTEXT`, and the parameters in the `Authorization` header, the query or a form body. The timestamp and the nonce are new on every send; **Advanced** has the realm, callback, verifier, version and the body hash. The secrets stay in the encrypted local store, with placeholders in the YAML, and Postman and Insomnia imports and exports carry the settings. `kurlo run` and `kurlo mcp` sign the same way.
- **Find and replace in a collection or a folder.** It searches the URL, params, headers, form fields, body, scripts, docs and the auth fields that hold no secret, with match case, whole word and regular expressions. Each match is previewed with its request, field and line, and is replaced one at a time, per request or all at once, with **Undo**.

- **More keyboard shortcuts.** `Escape` cancels a running request, `Shift Cmd/Ctrl C` copies it as cURL and `Shift Cmd/Ctrl F` opens find and replace. `Alt Cmd/Ctrl V` puts the response beside or below the request, `Alt Cmd/Ctrl 1`, `2` and `3` show collections, environments and history, and `Alt Cmd/Ctrl E` opens the environment picker. `Shift Cmd/Ctrl N` creates a collection, `Cmd/Ctrl O` imports one and `Shift Cmd/Ctrl R` opens the collection runner. `Alt Shift Cmd/Ctrl W` closes the other tabs and `Shift Cmd/Ctrl W` closes all of them. All of them can be remapped in Settings, and the command palette shows them.

### Fixed

- A gRPC metadata row or a Socket.IO event marked `secret: true` was written to the YAML in plain text. Its value now goes to the encrypted local store like any other secret row, and so does a secret row without an `id`, as an import or a hand-edited file can leave it.
- `kurlo run` sent an SSE request as an HTTP request with the method `SSE`. It now skips SSE, MCP and AI requests, as the docs say.
- The Collection Runner sent an MCP request as an empty HTTP request and showed the answer as the result of the call. MCP requests are now skipped, like AI requests.
- An Anthropic request with thinking on and a temperature, or a top P under 0.95, failed with a 400. Those settings are now left out while the model thinks.
- When an Anthropic stream broke before a thinking block was complete, the next reply failed with a 400. The tool calls of that turn are now left out of the history.
- An Anthropic answer that stopped with `pause_turn` ended there; Kurlo now sends the turn back so the model carries on, within the step limit.
- A provider that answered `200` with `Content-Type: text/event-stream` and no events gave an empty answer without an error; it now says so.
- An OpenAI-compatible server that refuses `stream_options`, `max_tokens` or `max_completion_tokens` is asked once more without it, and a tool call that arrives without an id gets one, so the next step does not fail.
- A late stream event of a cancelled AI send could land in the next send.
- An API key in a header such as `x-auth-token` or `anthropic-api-key` was not recognized, and Kurlo warned that the key was missing.
- Long AI answers no longer parse their Markdown again on every streamed chunk.
- The response layout button in the status bar did nothing when the editor was too narrow for the side-by-side layout; it is now disabled and says why.
- With Tengo as the script engine, a Postman, Insomnia or Bruno import put the collection's JavaScript into the Tengo fields, so every imported script failed on the first send. Imported scripts now always go to the JavaScript fields, and exports to those formats take the JavaScript scripts instead of the active engine's.
- The shortcut list in Settings could be scrolled sideways, which cut off the start of every name, and the keys of different shortcuts did not line up. The list no longer scrolls sideways, and single-character keys share one width, so the keys form columns.
- Git status and diffs could fail for a moment while a commit, pull, merge or rebase was running. A saved Git token that cannot be read is now reported as such instead of ending in a plain 401.

## [2.5.0] - 2026-10-24

### Added

- **AI requests.** A new request type sends a prompt to a language model: OpenAI, Anthropic, OpenRouter, Groq, Ollama, LM Studio, or any server with an OpenAI-compatible API. Choose the provider and the model next to the URL (**Load models** reads the provider's list), and write a system prompt and a prompt with `{{variables}}`. The answer streams into a conversation that shows the model's thinking, each tool call with its arguments and result, the stop reason, the time to the first token, the speed and the tokens in and out. **Reply** continues the conversation, **Raw** shows each stream as it arrived, and an answer cut off by the token limit or an error in the middle of a stream is called out where it happened. API keys come from `{{openaiApiKey}}`, `{{anthropicApiKey}}` and the like, so they stay out of the YAML.
- **MCP servers as tools for the model.** The **Tools** tab of an AI request lists the MCP requests in the workspace. Tick one, and when the model calls one of its tools Kurlo runs the call with that request's URL, auth and headers and gives the result back, step by step, until the model answers or the step limit is reached.
- **Markdown docs for every request.** The **Docs** tab has **Edit** with a live preview and **Preview**, which renders headings, lists, tables, code, links and images and adds a reference built from the request: the method and URL, the auth type, and the path variables, query params, headers and body with each row's description.
- **A status bar button for the response layout.** It puts the response beside or below the request; before, this was only in the command palette. Choosing the side-by-side layout yourself keeps it on editors down to 760 px wide.
- **`pm.response.llm()` in tests.** Test scripts of an AI request get the answer in one shape for every provider: the text, the tool calls with their parsed input, the stop reason, the tokens and the timings. Tests run once, after the last step.

### Changed

- **The AI conversation reads like a chat.** Answers are rendered as Markdown, the conversation uses the whole width of the panel, and the message field sends on `Enter` (`Shift+Enter` for a new line) without the system's spelling suggestions. **New chat** moved to the status line, and the Prompt tab says which text goes with every message and which only starts the chat.
- **Raw stays quick in long conversations.** Each step shows its URL and request body, steps are folded except the last, long bodies show their first 20,000 characters with **Show all**, and earlier sends no longer keep their raw bodies in memory.
- **The prompt field fits its text.** It starts at about six lines and grows as you write, up to the free height of the tab, instead of filling the whole tab.
- **The full address under the base URL.** An AI request shows where it sends the prompt, such as `POST https://api.deepseek.com/v1/chat/completions`, with the path Kurlo adds highlighted, so it is clear that the field takes the base URL.
- **Clearer errors when the model list does not load.** The provider and model box says what went wrong in a short title, shows the status and the address Kurlo asked (without its query string, where keys can hide), and suggests what to do next, such as checking the base URL or typing the model name.
- **Length limits for prompts.** The prompt and each chat message take up to 200,000 characters, the system prompt up to 50,000. A paste that does not fit is cut at the limit, a counter appears next to the label as you get close, and a longer prompt from an edited YAML file is refused when you send.
- **The method menu is shorter.** HTTP methods and the other protocols sit side by side.

### Fixed

- Clicking the provider and model box while it was open closed it and opened it again at once in the app; it now closes. The gRPC method picker had the same problem.
- With the response beside the request, the request side could be dragged so narrow that settings fields were cut off. Both sides now keep a minimum width, and settings rows stack when the panel is narrow.
- In a short window the prompt field of an AI request scrolled its text up under the top border.
- An invalid AI setting showed its error at the bottom of the tab, far from the field. Each field now shows what it accepts right below itself, and the number fields are narrower.
- The send button of the AI chat was nearly invisible in light themes while the message was empty.
- With the response beside the request, the lines of the response panel stopped short of the divider. The divider is now a single line with a wider grab area.
- On a narrow response panel the AI status line cut off the status code. Metrics now give way first, and **New chat** becomes an icon.
- A base URL with a query string, such as an Azure OpenAI URL ending in `?api-version=…`, got the API path after the query string, so the request went to a wrong address.
- A long provider error in the AI chat, such as a link in a "402 Payment Required" answer, ran past the right edge of the panel. The error now wraps inside the chat and shows the status apart from the provider's message, its links as links, and a hint at what to do, such as adding credits or lowering Max tokens.
- **New MCP request** on the Tools tab of an AI request added an empty request to the collection that stayed there when you closed it without saving. It now opens a draft.
- The code snippet of an AI request sent an empty request to the base URL: it had no prompt, no model and no body, so running it did nothing useful in any language. The snippet now posts to the full address, such as `…/v1/chat/completions` or `…/v1/messages`, with the JSON body Kurlo sends: the model, the system prompt and the prompt, and the settings you set, plus `anthropic-version` for Anthropic.
- A long model name, such as `gpt-4o-mini-2024-07-18`, pushed the metrics and **New chat** off the AI status line. The name is now cut with an ellipsis (hover shows it in full), and the status, the metrics and **New chat** stay in place.
- A long bearer token ran under the show/hide button in the Auth tab. The text now stops before the button.

## [2.4.2] - 2026-10-23

### Added

- **Path variables.** A URL like `{{baseUrl}}/users/:userId` now gets a **Path variables** section in the Params tab, below the query params, where you set the value of `userId`. Kurlo puts the value into the URL when it sends the request. Values can use `{{variables}}`, scripts can read and change them with `pm.request.pathVariables`, and they come across when you import from or export to Postman, Insomnia, Bruno and OpenAPI.

## [2.4.1] - 2026-10-22

### Added

- **A way to star Kurlo on GitHub.** Settings › Support has a link to the repository, and after your twentieth successful request a small "Star on GitHub" appears once in the status bar. It goes away for good when you click it or close it. The count stays on your machine; Kurlo still sends nothing anywhere.
- **`.keys` in test scripts.** `pm.expect(order).to.have.all.keys("id", "status", "total")`, `.to.have.any.keys(...)`, `.keys([...])` and `.key(name)` work as they do in Chai. A script that used them stopped with an error before.

### Fixed

- **A request body could be lost when the YAML named an unknown body type.** A request file with `bodyType: raw`, as Postman and Bruno call it, or another value Kurlo does not know, was read as having no body: `kurlo run` and `kurlo mcp` sent the request empty, and the next save from the app deleted the body from the file. `raw` is now read as the type in `rawBodyType`, and any other unknown type that has a body is read as text.
- **A change made outside Kurlo moved the open request to Params.** When an assistant, an editor or `git pull` changed the workspace on disk, Kurlo reloaded it and showed the open request on the tab saved in its file, usually Params, so you lost the Scripts or Body tab you were looking at. The request and response tabs now stay where they were.

## [2.4.0] - 2026-10-22

### Added

- **Ready-made prompts for AI assistants.** `kurlo mcp` now offers three MCP prompts, which Claude Code, Cursor and other clients show as commands: `sync_collection` finds the HTTP routes in your project's code and adds a saved request with tests for each one the collection lacks, `cover_endpoint` does the same for one endpoint such as `POST /orders`, and `debug_last_failure` explains why your last request failed. They tell the assistant to look for the server's address in the project and ask you before setting it, never to point an environment at production, and to delete nothing. With `--read-only` only `debug_last_failure` is offered.
- **`generate_tests` writes a request's tests from its response.** It sends the request and writes `pm.test` checks for the status, the `Content-Type` and a JSON schema of the body: the field types and which fields are required, never their values, so the tests do not break on the next order number and no data from the response ends up in your files. The response is saved as an example too, so the mock server serves it. For an API that is not running anywhere yet, `from: example` takes the status and body, or a schema, that the code returns, and the tests are ready for when the server is up. Tests the request already has are kept, and a 4xx or 5xx response is refused unless the call says that error is what it means to test.
- **`diagnose_last_failure` says why a request failed.** It takes the most recent request sent from the app that got no response, a 4xx or 5xx status or failing tests, and returns the error, the failed tests, the `{{variables}}` nothing sets in the active environment, how the response differs from the saved example (missing fields, changed types, another status), and hints for the likely cause: a server that is not running, a host that does not resolve, a token nothing has set yet, a method typed into the URL field, a pre-request script that threw.

### Changed

- **A JSON body can be passed as an object.** `save_request`, `save_example` and `generate_tests` took the body only as a string, so an assistant that sent `{"sku": "a"}` as JSON got an error. They now take either and store an object as formatted JSON.

## [2.3.2] - 2026-10-15

### Added

- **MCP requests reach the servers built before stateless MCP.** Kurlo spoke only the stateless 2026-07-28 revision, so most MCP servers in use today could not be opened at all. When a server does not answer the stateless call, Kurlo now opens a session the way revisions 2025-11-25, 2025-06-18 and 2025-03-26 expect (`initialize`, `notifications/initialized`, `Mcp-Session-Id`), sends every later call in it, and opens a new one if the server forgets it. The panel names the revision the server speaks.
- **Kurlo is listed in the MCP Registry.** `kurlo mcp` is published to the official MCP Registry as `dev.kurlo/kurlo`, so MCP clients and server directories that read the registry can find it and install it from `@kurlo/cli`.

### Fixed

- **Saved responses in History disappeared after a restart.** Kurlo keeps the response of each request you send, but forgot which history entries had one when it started again, so their responses could no longer be opened from History and `get_history_entry` in `kurlo mcp` returned no body. The link to the stored response, its size and content type now survive a restart, and the responses of entries that lost the link are found again.

- **Claude Code saw no Kurlo tools.** Claude Code talks to `kurlo mcp` with the 2026-07-28 revision of MCP, which requires every tool list to say how long it may be cached. Kurlo left that out, so Claude Code rejected the whole list and showed the server as connected with no tools. The list and the server description now carry the caching fields, and the server's instructions are short enough that Claude Code no longer cuts them off.

## [2.3.1] - 2026-10-14

### Fixed

- **Long release notes hid the update button.** When a new version had long notes, Settings → About squeezed the "is available" line and its **Install** button down to a thin grey bar. The status and button now stay put, and the notes scroll below them.

## [2.3.0] - 2026-10-14

### Added

- **AI agents can keep your collections up to date.** `kurlo mcp` has five new tools: `create_collection`, `save_request` (create a request or change only the fields named, with headers, body, GraphQL query, auth and JavaScript `pm.*` scripts), `delete_request`, `save_example` (keep the response of the last run, or a described one, as an example) and `set_variable`. They write the same YAML files the app does, through the same code, so an agent that adds an endpoint can add its request and tests to the workspace in the same commit. Secrets are never written: a token or password must be a `{{variable}}` reference, and secret headers or variables can only be changed in the app. Start the server with `--read-only` to offer only the tools that read and run.
- **Your agent sees what you just sent.** `kurlo mcp` has `list_history` and `get_history_entry`, which read the requests you send from the app with their responses, test results and script logs. Ask "why did my last request fail?" and the assistant reads it, nothing to copy. Secrets stay masked.
- **`kurlo mcp install` sets up your AI clients.** One command adds Kurlo to Claude Code, Claude Desktop, Codex, Cursor, VS Code, Windsurf and Gemini CLI, whichever are on the machine, and prints what it changed. It edits only Kurlo's entry and keeps the rest of each file, its order and its permissions; a file with comments is left alone and the entry to add is printed instead. When the Kurlo app is installed, clients start the server from the app, since apps opened from the Dock often cannot find `npx`. `--project` writes the repository's shared `.mcp.json` and `.cursor/mcp.json` with a relative workspace path, so the whole team gets the server by cloning. `kurlo mcp uninstall` takes the entries out again.
- **Protected environments.** Mark an environment **Protect from AI agents** in its ⋯ menu and `kurlo mcp` refuses to send requests with it or change its variables, so an assistant cannot reach production by picking the wrong environment. The mark is saved in the environment's file as `protected: true` and shared through Git.
- **Docs for language models.** kurlo.dev serves `llms.txt`, an index of the documentation, and `llms-full.txt`, all of it in one plain-text file.

### Changed

- **A token that only names a variable is stored as written.** A bearer token, password or API key of exactly `{{token}}` holds no secret, so it now stays in the request's YAML instead of moving to the encrypted local file. Someone who clones the workspace gets a request that works with their own environment instead of an empty placeholder.

### Fixed

- **Kurlo no longer overwrites files changed outside it.** With the app open, a request added by `kurlo mcp`, by an editor or by `git pull` in a terminal was deleted by the next save, because the app wrote back the workspace it had in memory. Kurlo now notices such changes within a second and reloads, and a save that races with one keeps both: the app writes its own edits and puts back every file it did not change itself. When both changed the same file, the app's version wins. The app and `kurlo mcp` also take turns writing, so neither sees the other's half-written save.

## [2.2.6] - 2026-10-11

### Added

- **The cookie sync extension comes with the app.** The Sync Cookies tab has a **Browser extension** section: pick Chrome, Edge, Brave or Firefox, and Kurlo puts the extension in a folder it opens for you, with the three steps to load it. No more cloning the repository. The extension carries the same version as Kurlo, and Kurlo refreshes the folder when it updates, so the browser picks up the new version the next time it starts or when you press Reload. A connected extension that is older than Kurlo is flagged in the tab. Each release also attaches the extension as `kurlo-cookie-sync-<version>-chromium.zip` and `-firefox.zip`.
- **`kurlo mcp` says which variables a request was missing.** When a request uses a `{{variable}}` that no environment, call override or script has set, `run_request` and `send_request` list it in `unresolvedVariables`, so an assistant that gets a `401` knows to run the login request first instead of guessing.

### Changed

- **Updates moved into About.** The Updates tab is gone. About shows the version, the update state with the one action that fits it (check, install, restart or try again), the automatic install switch and the notes of a new release, all in one place.
- **Large workspaces open and search fast.** With 10,000 requests the sidebar took about 24 seconds to appear and as long to search; it now takes about a second and a tenth of a second. A workspace with a long request history starts about twice as fast.
- **Saving many files at once is much faster on macOS.** Importing a collection of 10,000 requests took over two minutes to save; it now takes about four seconds. Kurlo flushes each file normally and makes one full flush to the disk at the end of the save instead of one per file.
- **Workspace files no longer carry `createdAt` and `updatedAt`.** Nothing read them, and cookie timestamps changed on every reload, which showed up as changes in Git. Files that still have them keep them until the item really changes.
- **A smaller Send button**, and a protocol badge such as `WS` or `GraphQL` that is as wide as its label once the protocol can no longer change.

- **Folders decide where a collection, request or environment belongs.** Changing a workspace or collection ID by hand, or in a pulled commit, no longer locks the workspace with one error for every file inside it. Kurlo follows the folder, keeps everything where it was, and rewrites the copied `workspaceId`, `collectionId` and `requestId` fields on the next save. Order entries for deleted files are skipped instead of reported.
- **One problem, one entry.** A copied collection or workspace folder is reported once, on the copy, and the original stays usable. The Git screen lists each file by name with its folder and a plain explanation, and only the problems that really pause saving remain: duplicate or missing IDs, a deleted parent file with files left inside its folder, and broken response examples.
- **A response example is one file.** The response body is now stored inside the example's YAML, as a readable block for JSON, XML and HTML, instead of in a separate `.body.json` or `.body.txt` file. Bodies saved the old way still load and move into the YAML on the next save.
- **History loads older commits as you scroll.** Reaching the end of the list fetches the next 60 commits without pausing the other Git buttons, so a repository with thousands of commits scrolls through without pressing **Load more**.
- **Diffs read like the file.** The Git screen no longer shows Git's own header lines (`diff --git`, `index`, `---`/`+++`), numbers each line by its place in the file instead of its place in the diff, and names each file when a commit touches several.
- **Edit YAML is a real editor.** It has syntax colours, line numbers and the same red underline as the JSON editor. Kurlo checks the file as you type with the parser that loads the workspace, so the editor and the Git screen always agree, and common YAML mistakes are explained in plain words instead of parser messages. ⌘S saves.
- **Changes lists only Kurlo files.** Other changes in the same repository are counted below the list instead of being shown as files Kurlo can neither commit nor discard.
- **A clearer branch picker.** Each branch is one line with its upstream beside it, the current branch is marked with a check, and a remote branch that already has a local branch is no longer listed twice: renaming or deleting it on the remote is in that local branch's ⋯ menu.
- **Files are named after what they hold.** A folder or file now always follows the name of the workspace, collection, request or environment inside it, so a pull request reads `collections/EF/requests/Obshchiy.yml` instead of `collections/Requests/requests/New-Request-3.yml`. Renaming in the app, editing `name` in the YAML, or pulling someone else's rename moves the file on the next save, and Git shows it as a rename. Cyrillic names are transliterated (`Общий` → `Obshchiy`) instead of becoming `item.yml`, names that differ only in case get separate files, which macOS and Windows need, and requests that share a name keep their numbered files when reordered. Opening or pulling never moves files by itself, and nothing moves while a file in the workspace is broken.
- **Changes and History share one panel.** The Git screen has two columns: a Changes | History switch on the left and the diff on the right. Picking a commit shows its message and diff there. History no longer needs its own column, its loaded-commit count or its refresh button: it refreshes after every Git action and whenever you come back to Kurlo with the Git screen open.
- **No more "Clean" label.** The toolbar showed "Clean" or "N changed" next to the branch, the same count the Changes tab and the status bar already show. It now shows only a merge or rebase in progress, the one state that needs attention there.
- **Git output opens in its own window.** It moved from a collapsed strip under the history to **Show Git output** in the ⋯ menu, and a failed command offers **Show output** next to its error.

### Fixed

- **Opening a workspace, switching branches or pulling showed changes you never made.** Kurlo rewrote request files to add a `settingsOverrides` block it had worked out from the request's own settings, and rewrote cookies with a new timestamp. A file whose content has not changed is now left exactly as it is.
- **A save interrupted while renaming or moving a request could lock the workspace** with two files claiming the same ID. Kurlo now keeps a short journal of the files a save writes and, after a crash, removes the leftover copy when it opens the workspace.
- **A save interrupted at the wrong moment could lose a newly entered secret.** The token was already replaced by a placeholder in the YAML but not yet stored in the encrypted local file. Kurlo now stores new secrets first.
- **Deleting a collection, cut short, could lock the workspace.** Its `collection.yml` was removed before the requests inside it. Kurlo now removes the files inside a folder first.
- **Exporting to Bruno or OpenCollection turned `{{token}}` into `{}`.** A value that starts with `{{` was written without quotes, which YAML reads as an object. Such values are now quoted.
- **Exporting to or importing from Insomnia dropped the pre-request and test scripts.** They now travel as Insomnia's `preRequestScript` and `afterResponseScript`.
- **Save to file wrote broken images, PDFs and archives.** A binary response body was passed through the window as text and lost bytes on the way. It now stays in Kurlo's backend, is saved byte for byte, and no longer turns a 100 MB download into half a gigabyte of window memory.
- **Send, Cancel, Send could end with no response and no spinner.** When the cancelled call answered late, it cleared the progress and showed "Request canceled" over the new call. A cancelled or superseded call no longer touches the screen.
- **Values a script set went to the wrong environment** when you switched environments while the request was running. They now go to the environment the request was sent with.
- **Search ignored the Starred section.** It stayed open with every starred request and pushed the results out of view.
- **The GraphQL explorer squeezed each field's arguments into a thin line**, and a schema with a default such as `filter: Input = {}` lost every field after it.
- **The Git sign-in hint said Kurlo does not store tokens.** Kurlo asks for a personal access token or an SSH key when a repository needs one and keeps the token encrypted; the hint now says so.

- **Response bodies saved as `.json`, `.xml`, `.html`, `.csv` or `.js` files never reached Git.** The Git screen only committed YAML, so a teammate who pulled the example got an error about a missing body file. The body now lives in the YAML itself.
- **A broken file in a workspace you were not looking at went unnoticed.** After a pull broke `workspace.yml`, Kurlo switched to another workspace and the Git screen showed only that workspace's problems. It now lists every broken file in the folder and names the workspace each one locks.
- **A request deleted in the app came back after a reload** when any other file in the same workspace could not be read. Kurlo now keeps only the unreadable file, or the folder of an unreadable `collection.yml` or `workspace.yml`, and cleans up the rest as usual.
- **Changing a workspace ID back left stray changes.** Kurlo had rewritten the references inside the folder for the new ID, and after the ID was restored they stayed changed until the next edit. Kurlo now corrects references, and the order in `kurlo.yml`, as soon as it loads the folder, touching only those lines and keeping comments.
- **`name: 404` or `method: 42` in a request file stopped the workspace from loading.** Unquoted numbers and other wrong value types in hand-edited YAML are now read as text where text is expected, and a value of the wrong shape falls back to its default.
- **A file written by a newer Kurlo was read as if it were the current format.** It is now reported and left untouched.
- **A save cut short, by a crash or a power loss, could leave the workspace locked.** Kurlo now writes each parent file before the files inside it, so an interrupted save always leaves a folder that loads.

- **The workspace JSON Schema rejected the files Kurlo writes.** It required fields Kurlo leaves out, such as `filesystemName`, a default `method` or an empty `auth`, missed the `cookies` of a workspace, and lacked newer values such as the `mcp` request type, `inherit` auth and the `password` and `device_code` grants. Every file Kurlo writes is now checked against it in the test suite. It also moved to JSON Schema draft-07, which IntelliJ-based IDEs and the YAML language server read fully.

- **Two first saves at the same moment could refuse each other** with "kurlo.yml is missing but workspace files remain", for example the app and `kurlo run` writing a new folder together. Kurlo now checks again before reporting it.

## [2.2.5] - 2026-10-06

### Added

- **`kurlo run` and `kurlo mcp` without the desktop app: `npx -y @kurlo/cli`.** The command line is now on npm as `@kurlo/cli`, with prebuilt binaries for macOS, Linux and Windows on x64 and arm64. npm downloads only the one your machine needs, about 8 MB. An AI agent connects with one line on every system, for example `claude mcp add kurlo -- npx -y @kurlo/cli mcp`, instead of a path into the app bundle, and a CI runner can run a workspace's tests with `npx -y @kurlo/cli run ./workspace --env CI` without installing the app. It is the same engine as the app, and with no workspace argument `kurlo mcp` still serves the workspace the app has open. See [MCP server](https://kurlo.dev/docs/guides/mcp-server/) and [CLI runner](https://kurlo.dev/docs/guides/cli-runner/).
- **An AI assistant can check a call the way a browser would.** `run_request` and `send_request` in `kurlo mcp` take `browserOrigin`, the origin of the page that would make the call, and `browserCredentials`. The call then goes out with browser emulation: the `Origin` and browser headers, the CORS preflight when one is needed, and the CORS error a browser would raise. An assistant asked "why does my frontend get a CORS error" can now reproduce it instead of guessing.
- **`list_requests` searches.** Its `query` argument keeps the requests whose path, method or URL contains every word, ignoring case, so an assistant in a large workspace finds `POST /orders` with `post orders` instead of reading the whole list.

### Fixed

- **Scrolling a large response fast showed an empty pane.** A body long enough to be drawn a screen at a time — `jsonplaceholder.typicode.com/photos` is 35,000 lines — went blank while its scrollbar was dragged, showed its cut-off edge on a fast trackpad flick, left the line numbers behind the text, and flashed on `End` or `Cmd+↓`, because the browser scrolled before the lines for the new position were drawn. Kurlo now scrolls such a body itself, the way code editors do: the scrollbar, the wheel and trackpad, and the arrow, page, `Home`, `End` and `Cmd+↑/↓` keys move the view and draw its lines in the same frame.
- **CORS checks stopped at the first redirect.** A same-origin request redirected to another origin skipped CORS entirely, a cross-origin redirect response was followed without its own `Access-Control-Allow-Origin`, and no preflight was sent to a new origin reached by a redirect. Kurlo now applies the browser's rules on every hop: the redirect response must pass CORS, a non-simple request is preflighted at the new origin, a chain that leaves one cross origin for another sends `Origin: null`, cookies are dropped once the chain leaves the page's origin without *Include browser credentials*, `Authorization` is removed when the origin changes, a `Location` carrying a username or password is refused, and `Sec-Fetch-Site` stays `cross-site` for the rest of the chain. Methods follow the browser too: a `302` keeps `PUT` and `DELETE` and only turns `POST` into `GET`, and a `303` drops `Content-Type` along with the body, so it no longer triggers a preflight of its own. SSE follows the same redirect rules.
- **Some request headers counted as CORS-safelisted when a browser would preflight them.** Kurlo looked only at a header's name and, for `Content-Type`, its media type. It now checks the value as the Fetch standard does: at most 128 bytes, no characters such as `"`, `(`, `:` or `@`, only language-tag characters in `Accept-Language` and `Content-Language`, a single `bytes=N-` or `bytes=N-M` in `Range`, and no more than 1 KB across all of them. `Range: bytes=-500`, a quoted `boundary` or a long `Accept` now preflight, as they do in Chrome.
- **Global variables never reached `{{...}}`.** A value from **Environments → Globals** was left in the request as a literal `{{name}}`, so the send failed with *unresolved variable*. Globals now resolve as the lowest scope — a collection or environment value with the same name still wins — and show up in the variable autocomplete. In the Collection Runner, a global one request writes is used by the requests after it.
- **A value stored by a pre-request script came one send late.** Templates were filled in before the script ran, so `pm.environment.set("token", ...)` followed by `Authorization: Bearer {{token}}` sent the previous token — or the literal `{{token}}` on the first send. Kurlo now resolves the request again after the script, in the app and in `kurlo run`, while the script still reads the request it was given and keeps its own `pm.request` edits. A secret the script writes is masked in the trace and the script log like any other.
- **Redirects dropped the `Authorization` header on the same host.** With *Follow Authorization header* off — the default — even `/api` → `/api/` lost the token and came back 401, and turning the setting on still dropped it on another host. A redirect on the same host now keeps the header, the setting keeps it across hosts as documented, and a redirect from HTTPS to plain HTTP always drops it.
- **The Collection Runner hid the data row from scripts.** `pm.iterationData.get(...)` returned `undefined` and `pm.info.iteration` and `pm.info.iterationCount` stayed `0` in a data-driven run from the app; only `kurlo run` passed them. The runner now hands each request its row, its 1-based iteration and the total.
- **Variables with non-Latin letters, spaces or colons were never filled in.** `{{токен}}`, `{{api key}}` and `{{api:key}}` were sent as written although the editor showed them as known. Any name without `{` or `}` resolves now, as in Postman, and autocomplete offers them.
- **`kurlo run` did not resolve a variable built from other variables.** A `baseUrl` of `{{scheme}}://{{host}}` worked in the app but reached the CLI as `{{scheme}}://...`; the CLI now resolves nested values the same way.
- **A request timeout of `0` still stopped at 30 seconds.** The documented way to switch the timeout off fell back to the default, and the field would not go above 5 minutes, so *Send and Download* of a large file could not finish. `0` now waits as long as the server takes, in the app and in `kurlo run`, and the field has no upper limit. A request that sets no timeout still stops after 30 seconds, or after its collection's default.
- **The mock server replayed compressed examples unreadably.** An example captured from a gzip response kept its `Content-Encoding: gzip` header but stored the decoded body, so every client of the mock failed with *invalid gzip header*. The mock no longer forwards `Content-Encoding`.
- **A `POST` to a streaming endpoint hit a dead end.** An endpoint that answers with `text/event-stream` — the streaming mode of most LLM APIs — was refused with *Switch to SSE mode*, but the `SSE` method only subscribes with a bodiless `GET`. Any method other than `GET` now reads the stream to the end and shows the raw events as the response.
- **A quiet WebSocket dropped after 90 seconds.** With keep-alive pings turned off (`-1`, as the docs suggest for servers that dislike them) or set above 90 seconds, a connection with no traffic was closed by a fixed read deadline. The deadline now follows the keep-alive interval and is off when pinging is off.
- **Handshake headers copied from DevTools broke WebSocket and Socket.IO connections.** `Sec-WebSocket-Key`, `Sec-WebSocket-Version` and `Sec-WebSocket-Extensions` failed the connection with *duplicate header not allowed* and then retried in a loop. Kurlo now leaves them out, says so in the message list, and connects.
- **A hand-written `Content-Type: multipart/form-data` broke form bodies.** It replaced the header Kurlo generates, so the boundary went missing and the server could not read the form. Kurlo now sends the boundary of the body it built, and warns when it replaces one you typed.
- **Socket.IO events carrying binary data never appeared.** Binary events and binary acknowledgements — anything sending a `Buffer` — were dropped. They show up now, with each attachment as `{"_binary": "<base64>", "size": n}`.
- **Pasting a cURL command lost or changed the body.** `-d a=1` became a `text/plain` body instead of the urlencoded form curl sends, `--json` was ignored and the request went out as a bodiless `GET`, the `$'...'` quoting that Chrome's *Copy as cURL (bash)* uses for bodies with quotes or non-ASCII text came out garbled, `-d @file` sent the literal text `@file`, and `-b` beside a `Cookie` header produced two `Cookie` headers.
- **Generated code snippets did not run.** The HTTPie snippet left the URL and headers unquoted — `&` in a query string or `Bearer <token>` split the command — and sent the body as a JSON field instead of raw. PHP and Kotlin strings expanded `$`, which broke GraphQL queries such as `query($id: ID!)`, and Ruby expanded `#{...}`. Swift and Rust escapes now use their own `\u{...}` form, a urlencoded body carries its `Content-Type`, custom methods work in C#, Ruby and Rust, and multipart and file bodies are generated for every language instead of being dropped.
- **Arrow keys in a response or a dialog switched the request.** With a response body focused, `↓` scrolled it and opened the next request in the sidebar at the same time, `←` collapsed its collection, and `Backspace` offered to delete the request; the arrows in Settings, menus and tab bars reached the sidebar the same way. The sidebar's arrow and `Backspace` shortcuts now act only outside responses, dialogs, menus and tab bars.
- **Arrow keys in Settings skipped a section.** `↓` from *Theme* went to *Shortcuts* instead of *Proxy*, because the list moved once for each of two key handlers. It moves one section at a time now.
- **The Collection Runner's checkboxes looked cleared during a run.** While a run was in progress every selected request showed an empty box. They stay checked and dimmed now, at the size of every other checkbox.
- **Response search counted matches it did not highlight.** A search across a key and its value, such as `name": "al`, reported a match but highlighted nothing, so *next match* went nowhere. Such matches are highlighted now.
- **Server-sent events were parsed loosely.** An event with an empty `data:` line was dropped, an event's id did not carry over to the events after it, and streams using bare carriage returns or starting with a byte-order mark lost events. The parser now follows the event-stream specification; an event-only block is still shown, which helps when debugging.
- **Force push could overwrite a teammate's work.** Kurlo fetches when a workspace opens, and after a fetch `--force-with-lease` no longer protects commits the fetch downloaded. Force push now also passes `--force-if-includes`, so it refuses while the remote holds commits your branch has not taken in.
- **Common Postman script helpers were missing.** `pm.variables.replaceIn`, `xml2Json`, the legacy `tests["..."]` object, `responseBody`, `responseCode`, `responseHeaders`, `responseTime` and `postman.setEnvironmentVariable` / `getEnvironmentVariable` / `setGlobalVariable` and friends now work, so older collections run without rewrites; `postman.setNextRequest` says why it is not supported.
- **OpenAPI import ignored servers set on a path or an operation.** Such requests went to the document's `{{baseUrl}}`; they now use their own server.

## [2.0.0] - 2026-10-01

Kurlo 2.0 is a new look — the Graphite design, from the window chrome to every screen, menu and dialog — plus MCP requests, a command palette, a page for each history entry, the last run of each collection, and environments side by side. It needs macOS 12 or later.

### Added

- **A command palette.** `Cmd/Ctrl K` still finds a saved request by name, URL, method or collection, and now also runs Kurlo's commands from the same box: send, save, duplicate or rename the open request, copy it as cURL, create a request, collection or environment, import, jump to history, the runner, the mock server, Git, cookies or settings, show or hide the sidebar and the code panel, put the response beside or below the request, switch theme. Arrow keys move through the list; a leading `>` lists commands only; every command bound to a shortcut shows it, including one you reassigned.
- **A page for each history entry.** Clicking a row in History opens what was sent — method, URL, headers, auth type and body — next to what came back: status, time, size, and the stored response in the same viewer as the response panel. It links back to the request it came from, copies the request as cURL, deletes the entry, or opens it in the editor. It is a tab of its own, so the request you were working on stays where it was.
- **Each collection remembers its last run.** The runner shows a collection's most recent results — with when it ran — as soon as you open it, instead of an empty page, and the collection's own page sums it up in one line that links there. Runs are kept in the encrypted local profile, not in the workspace YAML, so they never reach Git.
- **MCP is a request type.** Kurlo can call a [Model Context Protocol](https://modelcontextprotocol.io) server the way it calls anything else — point it at the endpoint, press *Discover*, pick a tool, fill the arguments, send. The protocol's `2026-07-28` revision is stateless: no handshake, no session, every call a single HTTP POST. That is what makes this a request rather than a subsystem, and it is why an MCP call can be saved in the workspace, diffed in review, run by the collection runner and asserted on by a test script, alongside the REST endpoints next to it. `kurlo run` picks them up in CI with no new flag.
- **The wire is a first-class view, not a debug pane.** Every other MCP client exists to hide the protocol from a model; when a tool call fails inside an agent you are told the tool failed. Kurlo shows the JSON-RPC envelope it sent, the `Mcp-Method` / `Mcp-Name` / `MCP-Protocol-Version` headers it mirrored into HTTP, the individual frames when the server answered with a stream, and the progress notifications that arrived before the result — beside the timings, TLS and redirect timeline it already collects for every request.
- **Discovery asks only what the server says it has.** `server/discover` first, then `tools/list`, `resources/list` and `prompts/list` for the declared capabilities alone. Choosing a tool seeds the arguments editor from that tool's own input schema, and the arguments are checked for being a JSON object before anything leaves the machine.
- **Kurlo checks the server against its own promises.** When a server publishes an `outputSchema` and then sends `structuredContent` that contradicts it, the mismatch is reported as a warning and the content is still shown — the server is at fault, not the person reading it. A tool whose `x-mcp-header` annotations the specification forbids is refused with the reason named, rather than silently dropped from the list the way a conforming agent client drops it.
- **The protocol owns its headers.** `Mcp-Method`, `Mcp-Name`, `MCP-Protocol-Version` and `Mcp-Param-*` are derived from the call, including the `=?base64?…?=` encoding a name or parameter needs when it is not plain ASCII. A hand-written header of the same name is replaced and you are told, because a server must reject a request whose headers and body disagree.
- An `input_required` result — the server asking for more before it can finish — is carried back whole, with the schema it asked against and the opaque state to replay, and a retry sends the answers as `inputResponses`.
- Auth, proxy, client certificates, redirects, cookies and the response cap are the ordinary HTTP ones. An MCP call is an HTTP request and carries the same settings, so signing in to a remote server is the OAuth flow Kurlo already has.
- **Discover changed its own label while it worked**, so the button resized and dimmed at the same time and read as a second, ghostly button flashing behind the first. It keeps its label and a reserved width now, and says it is working the way the rest of the application does — with a spinner beside the text it already had.
- **The URL field filled a fraction of the bar.** The request bar is a three-column grid whose first column holds the HTTP method picker; MCP has no method picker, so the URL landed in that column and shrank to its own content while the space to the right of Send stayed empty. It uses the two-column layout WebSocket, Socket.IO and GraphQL already use, and the placeholder names what belongs there — the MCP endpoint, not a cURL command.
- The panel is built from the application's own parts rather than a private set: the field labels, the select and the secondary button are the ones every other panel uses, at the same height, radius and type size, and the response side is the response bar, mini-tabs and placeholders that gRPC and HTTP already share. The shared select picked up two fixes on the way: **it measures the space it has and scrolls inside it, opening upwards when there is more room above**; and it **closes when you click away or press Escape**, where before it only closed when focus happened to move somewhere focusable, so a menu could sit open over the panel behind it. Both were already wrong everywhere — the MCP method list, at seven entries in a short pane, is simply the first one that made them obvious.

- **Not in this release**, and named rather than left to be discovered: the **stdio** transport, so a server launched as a local command cannot be reached yet — that needs process supervision and a consent model for running arbitrary commands, and it is the larger half of the work. Also out: protocol revisions before `2026-07-28`, `subscriptions/listen`, and sampling — a server asking Kurlo to run a model inference is asking Kurlo to have one, and it declines with a reason you can see.

- The error card in a code editor closes as soon as you type, instead of showing the old message until the pointer moves; Escape in a dropdown closes only the dropdown; a rejected variable name is kept in the field to fix; a right-click inside the collection rename field gets the normal Cut/Copy/Paste menu; history rows fit `OPTIONS`.
- **No text runs into other text or gets cut mid-word at any window size.** A narrow request column drops the Description column rather than squeezing it under *Bulk edit*, and stacks the auth type over its fields; the response search floats over the body instead of squeezing the status until "200 OK" was cut; the status line and the stream summaries drop their trailing numbers whole when they run out of room; Git lays changes and diff side by side with history below in a narrower window; *Decode* keeps its width.

### Fixed

- **A dropdown inside a labelled field reopened after you picked an option on macOS**, so choosing a collection in the runner left its menu open over the page. The system WebView forwards a click inside a label to the label's first control — the dropdown's own button. Picking an option no longer passes the click on, and the end-to-end suite now also runs in WebKit, the engine Kurlo uses on macOS, which is how this was found.
- **A stored history response over 2 MB could not be read back.** The response was cut at 2 MB after it had been turned into JSON, which left the file unreadable, so *View response* and *Open* reported an error for exactly the large responses you would want to look at again. The body is now shortened before it is stored, the rest of the response is kept whole, and the entry says it was cut.
- **Line numbers keep up while a response scrolls on macOS.** Each number was lifted into its own layer and, in a large response, moved sideways by a script that ran after every scroll event; the system view scrolls on its own thread, so fast scrolling showed code without numbers and a sideways scroll could leave the number column stranded in the middle of the text. A response that wraps now draws its numbers with the text, and a large one keeps them in a single column pinned by the browser itself, so it stays put at any scrolling speed.
- **Switching an existing request to a type that does not have the open tab left the editor blank.** `selectRequestType` reconciles the tab for every other transport but had no MCP branch, so a request switched from HTTP kept `params` — a tab MCP does not have — and the editor showed a tab strip with nothing under it. It now lands on Arguments, keeps a tab both types share, and clears the HTTP body, which an MCP call does not carry.
- **The mock server only answers pages served from this machine now.** It reflected whatever `Origin` a request carried back as `Access-Control-Allow-Origin` and set `Access-Control-Allow-Credentials: true` alongside it, which meant any site open in the browser could read the mock's responses — and the 404 body helpfully lists every route, so it could map the collection first. A mock is built from responses recorded against real APIs; that is not something to hand to a page on another host. Loopback origins are allowed on any port, since a dev app on `localhost:5173` is the client this exists for, and anything else gets a `403` with no CORS headers and a row in the request log naming the origin that was turned away. `Access-Control-Allow-Headers: *` and `Expose-Headers: *` went out with it: a wildcard is ignored on a credentialed response, so the two headers were not doing what they looked like they were doing — the requested headers are now echoed back, and the response names the headers it actually exposes, which is what lets a client read `X-Kurlo-Mock-Example`.
- **An example edited with the mock panel closed was ignored.** The reload lived in an effect inside the panel, so it only ran while the panel was mounted — click a request and edit its example, and the server carried on answering with the version you had just replaced. That is the failure the reload exists to prevent, and it happened in the ordinary case, because editing an example means being in the request editor rather than on the mock tab. It now belongs to the app, and it follows the collection the server is serving rather than the one the panel has selected, so a reload can no longer switch the mock onto a different collection behind your back.
- **A reload threw the request log away and could kill the running server.** Every reload stopped the server and started a new one, which cleared Kurlo's copy of the log; the panel kept its own, but reopening the tab re-read the empty one, so the log the documentation promised survives a reload lasted until you looked at it from somewhere else. Worse, if the port had been taken in the meantime the restart had already torn down a working server. Reloading now swaps the routes on the server that is running — the port never moves, connections are not dropped, and the log is simply not touched. A move to a different port binds the new one before giving up the old one, so a refused bind leaves the mock answering where it was.
- **A request the client gave up on vanished from the log.** When *Reproduce recorded response times* was on and the client timed out during the delay, the handler returned without recording anything — so the one request most worth seeing, the one your client abandoned, was the one the log did not show. It is now listed with the example that would have answered and the reason it never did.

## [1.8.0] - 2026-09-11

### Added
- **Sync Cookies is a real feature, not a disabled tab.** The cookie jar had a *Sync Cookies* tab that was hard-disabled since it was drawn — Postman's layout with nothing behind it. It now pairs Kurlo with a browser extension so the session you already have in Chrome, Edge, Brave or Firefox is the session Kurlo sends with, instead of copying a `Cookie:` header out of DevTools after every login.
- **Pairing is a click, not a copy-paste.** The extension finds Kurlo by itself (it scans ports 3199–3203) and asks to connect; Kurlo shows the request with a six-digit code, the extension shows the same code, and approving it hands over a token. Matching codes is what stops anything else on the machine from being approved in the browser's place, and after the first approval the browser reconnects on its own. *Pair manually* with a copyable code stays as the fallback for a non-default port.
- **The transport is a WebSocket, so cookies arrive as they change.** Every cookie the browser sets, updates or clears for an allowlisted domain is pushed within a second; a full snapshot on connect and every five minutes reconciles anything missed while the browser was closed. The allowlist travels the same socket, so adding a domain in Kurlo takes effect at once and removing one stops it being read immediately.
- Cookies flow one way, browser into Kurlo, through three separate gates: a loopback-only listener that is off until you turn it on, an approval you give in Kurlo before any token exists, and a domain allowlist enforced twice — Kurlo refuses cookies for domains you did not list, and the browser only lets the extension read the domains you grant in its popup. A public suffix like `co.uk` is refused with an explanation rather than accepted and quietly ignored. Only extension origins are answered at all; a web page probing the port gets a `403`.
- A snapshot is authoritative for the domains it covers: Kurlo replaces whatever the jar held for them, so signing out in the browser clears the cookie in Kurlo too. Domains outside it are untouched, and a domain the extension could not read is left out rather than reported as empty — which would otherwise read as "the browser has none" and clear it.
- Synced cookies land in the workspace jar you have open and follow you when you switch workspaces. The bridge closes on quit and reopens on the next start if you left it on, keeping the token so a paired browser never needs approving twice. **Disconnect it** mints a new token and drops the browser immediately.
- The extension ships in the repository under `apps/extension` (Chromium manifest plus a Firefox event-page manifest), loaded unpacked.

### Fixed
- **Disconnecting a browser left its extension retrying forever.** Kurlo closed the socket without a close frame, so the browser saw a generic "connection lost" and kept reconnecting with a token that would never be accepted again — the extension sat on *Reconnecting* until someone pressed Forget by hand. Kurlo now closes with `1008` when it disconnects a browser on purpose and `1001` when it is merely shutting down, and the extension treats a socket that never opens while Kurlo still answers as the same signal: it drops the dead token and asks to connect again.
- **A burst of cookies re-read the whole jar once per cookie.** A login that sets a dozen cookies produced a dozen full jar reads and as many store writes queued behind them; the refresh is now debounced, so a burst costs one.
- **A snapshot too large for Kurlo looped instead of explaining itself.** The extension now checks the count and the payload size before sending, and says which way to narrow the allowlist rather than retrying the same oversized push every five minutes. It deliberately sends nothing in that case: a truncated snapshot is authoritative, and would have cleared the cookies that did not fit.
- **A domain the browser was never granted looked like it was syncing.** Kurlo now names those domains in the Sync Cookies tab and marks their chips, instead of showing a healthy connection that silently covers fewer domains than the list suggests.
- **A pairing request could be approved after it expired.** Expiry now wins over a late approval.
- **The Open log folder button in Settings had stopped doing anything.** Wails 2.13 added a URL validator to `BrowserOpenURL` that rejects the `file:` scheme outright — and, for good measure, any path containing a space, which every macOS `Application Support` path has. The call was refused with a line in the frontend log and no error anywhere the user could see it, so the button looked dead. Kurlo now hands the folder to the platform file manager directly (`open`, `explorer`, `xdg-open`), and a failure is reported in the row instead of being swallowed.

## [1.7.0] - 2026-09-09

### Added
- **A local mock server, built on saved examples.** Point it at a collection and Kurlo serves every example it holds over HTTP, so a client can be written against an endpoint that does not exist yet — or against the failure cases a real staging environment will not produce on demand. This is what examples were leading to: they already stored the response, the request that produced it, and a path template (`/orders/8123` captured as `/orders/:id`), so the mock is matching rather than a new kind of data. Postman's equivalent lives in the cloud and needs an account; this one is a port on your own machine, serving files that are in your Git history.
- Routing takes the method and the path template, with a literal segment beating a parameter, so `/pets/featured` wins over `/pets/:id` no matter which example was captured first. An example that recorded query parameters only answers requests carrying them, which is how one endpoint serves its empty, its full and its error case from three examples. OpenAPI-style `{petId}` segments match the same way `:petId` does.
- The server binds **loopback only** — a mock made from real recorded responses is not something to put on the network by accident — and answers CORS preflight for any origin, since the first client to hit it is usually a browser app on another port. A request that matches nothing gets a 404 naming the routes that do exist, rather than a bare status.
- **Requests-served log**, live, showing what a client actually asked for and which example answered. The unmatched rows are the useful ones: they are the difference between "my fetch is wrong" and "no example covers this yet". The log is kept on the Go side too, so reopening the tab shows what happened while it was closed.
- **Reproduce recorded latency**, off by default: each example knows how long the real response took, which is a cheap way to see a loading state that a local mock otherwise never shows.
- The mock **reloads itself when you edit an example** it is serving, so the running server never answers with something you already changed. The request log survives the reload, because from a client's point of view the server never went away — and a rename, which changes nothing a client can observe, does not bounce it.
- **Two examples that would answer the same request are called out**, with the losing rows marked in the list. Only the first match ever replies, so without this the second one looks broken rather than shadowed. Examples separated by a recorded query are not flagged: that is the ordinary way to serve an empty and a full case from one path.
- Each route copies **its own URL**, not just the base, and clicking a route — or a matched row in the log — opens the example behind it.

### Fixed
- **Opening a saved request marked it unsaved straight away**, in manual-save mode, without anything being edited. The dirty check compares a serialized fingerprint of the editor against what came back from the store, and it used `JSON.stringify`, which preserves the order keys were inserted in. The normalizer and the editor build the auth object in a different order — `oauth2Audience` sits in a different place in each — so the two strings differed while the data was identical, and the indicator that is supposed to mean "you changed something" lit up on every request you so much as clicked. The fingerprint now sorts object keys, while leaving arrays alone because row order is meaningful: `?a=1&a=2` is not `?a=2&a=1`. Present since the audience field landed, not new to this release.
- **Eighteen styles across the app silently did nothing**, because they named a custom property that was never defined: `--text-1`, `--surface-2`, `--bg-2`, `--input-bg` and `--font`. A `var()` naming a property nothing defines is not an error — the declaration is dropped and the element falls back to an inherited value or a browser default, which reads as a styling oversight rather than a typo. The response panel took the worst of it: the Diff view's added and removed lines never set their own text colour, and the `… unchanged lines` marker had no background at all. Every one now names a real token, the UI font has a `--font-ui` token to match `--font-mono`, and a test scans the stylesheets so a var() that resolves to nothing cannot land again.
- **A request that failed to send crashed the response panel**, replacing the message that would have explained the failure with `TypeError: null is not an object (evaluating 'response.headers.find')`. `HttpResponse.Headers` is a Go slice that is nil on every path where no response arrived — a DNS or TLS failure, a refused connection, an unresolved variable, a bad client certificate, a pre-request script that threw — and a nil slice serializes to `null`, while the generated binding types the field as an array and the history recorder read it on every send. The sender now guarantees an array, and the recorder tolerates its absence so an entry stored by an older build cannot crash the panel either. The practical effect is that you can finally see *why* a send failed.

### Changed
- **The mock server panel and the documentation caught up with the app.** The panel now uses what everything else uses — the runner's two-column workspace shape, the shared select, the method and status badges, and the real design tokens, which is what makes it follow the light theme. Response examples shipped in 1.5.0 with no guide at all and the mock server builds directly on them, so both are written now; three pages that still told readers Kurlo had no mock server are corrected, and Import & export gained the OpenAPI-from-URL flow that landed in 1.6.0.

## [1.6.0] - 2026-09-05

### Added
- **Import an OpenAPI or Swagger spec from a URL.** Every import path took a file, so bringing in a spec meant downloading it first — and a spec URL is what teams actually pass around, because it is the one that stays current. **Import collection → OpenAPI / Swagger from URL** takes the link, fetches it, and builds the same collection the file import would: `{{baseUrl}}` as a collection variable, path parameters seeded from the spec, declared security schemes mapped onto each request's auth. The fetch goes through the Go sender rather than the WebView — a spec host has no reason to send CORS headers, and it brings redirect following, the proxy settings a corporate network needs, and the response cap. A link with no scheme is read as `https`, cookies are left out of the request, and the collection is named from the spec's `info.title`, falling back to the host rather than to a generic path segment like `/v3/api-docs`.
- A URL that turns out not to be a spec says which of the several things went wrong, in a dialog rather than a toast that has gone by the time it is read. The one worth naming: pasting the **Swagger UI page** rather than the document it renders is the most common mistake by far, and "could not parse" would send someone looking at the wrong end of it — so that case says so, and names where the document usually lives.

### Fixed
- **An upload went out with no `Content-Length`.** `net/http` works the body length out for itself only for the in-memory reader types, so a binary file body and a multipart body — both streams — were framed `Transfer-Encoding: chunked`. That is exactly what the services people upload to refuse: an S3 presigned `PUT` requires a declared length, so does Azure Blob, and a fair number of nginx and API-gateway setups answer `411 Length Required` and nothing else. Both now declare their exact size. The multipart length is computed from the rows without writing anything, and a test measures a real body against that arithmetic so the assumption it makes about `mime/multipart`'s framing cannot drift silently; a file that cannot be measured leaves the length unknown and streams chunked as before. The same gap left `GetBody` empty, so a `307`/`308` redirect had nothing to replay and abandoned the send — a file body now survives one.
- **The Auth tab silently replaced a header written by hand.** Auth is applied after the header rows, so configuring bearer auth *and* typing an `Authorization` header sent the tab's value and discarded the row — with the row still on screen, looking sent. The precedence is unchanged (it is the safe one to keep), but the response panel now names what was replaced, next to the notice that already explains dropped framing headers. Covers `Authorization` for bearer, Basic and OAuth 2.0, and whatever header name an API key is configured under.
- **AWS Signature v4 signed the path with one URI encoding.** S3 wants exactly that, but every other service asks for the path to be normalised per RFC 3986 and then encoded *twice*. Any path carrying a character that needs escaping was therefore rejected with `SignatureDoesNotMatch` — including the ordinary shape of a Lambda invoke URL, which carries the function ARN, colons and all, in the path. S3 keeps its own rule.
- **A form part's `Content-Type` was lost when a cURL command was pasted.** The parser has read curl's `;type=` suffix since 1.5.0 and the export writes it, but the paste path dropped it while building the rows — the one place that round trip was broken, and the difference between an upload an API accepts and one it rejects on the MIME type.
- **Copying a request as cURL or as a code snippet mislabelled the body.** Only JSON and GraphQL bodies got a `Content-Type`, so an XML, HTML or plain-text body arrived as curl's own default, `application/x-www-form-urlencoded` — a different request from the one that was copied. Every string-payload body type now declares what the sender declares, taken from one table shared by both generators. The body also goes out as `--data-raw`, since `-d` reads a leading `@` as a filename.
- **`-k`, `--max-time` and `--proxy` were discarded when a cURL command was pasted.** Each maps onto a request setting Kurlo already has, so the pasted command produced a request that quietly behaved differently — most of all `-k`, whose entire purpose is that the endpoint's certificate does not verify.
- **A second value for a query parameter already in the URL was dropped.** Folding the URL's query into the params table deduplicated by key alone, so `?tag=a` in the URL with `tag=b` in the table sent only `tag=a`. Only the row the two-way sync mirrored — same key *and* same value — is folded away now. Repeated keys are the case the sender goes out of its way to preserve, since the APIs that sign a query string verbatim depend on it.
- **Capturing a response example rewrote the body.** It was parsed and re-serialised even when the redaction sweep found nothing, which is lossy in ways that matter for a file whose whole job is to record what an endpoint really returned: an id past `Number.MAX_SAFE_INTEGER` came back a different number, and a duplicate key collapsed. The bytes are now left alone unless something was actually redacted.
- **A `CR` or `LF` in a multipart field name could inject headers into the part.** Kurlo escapes those, but only on the branch taken when the row names its own `Content-Type`; without one it fell through to `mime/multipart`'s helpers, which escape quotes and leave line breaks intact. Every part is now written through the same escaping.
- **An empty `form-data` or `x-www-form-urlencoded` body was framed on a `GET`.** The raw body types already treated an empty payload on a method that conventionally carries none as no body at all; these two did not.

### Changed
- **Code comments were removed across the repository**, at the maintainer's request. What stays is anything that instructs a tool rather than a reader: `//go:build` and `//go:embed`, `//nolint`, `eslint-disable`, `svelte-ignore`. Each language was cut with its own parser rather than a regular expression — Go through `go/scanner`, TypeScript and the Svelte `<script>` blocks through the TypeScript parser, stylesheets through a CSS scanner that tracks strings — so a `//` inside a string or a regex literal was never mistaken for a comment. Go token streams were compared before and after across every file and are identical, the YAML workflows were parsed both ways and compared as documents, and the generated Wails bindings were left alone because CI checks them against the generator's own output.
- The README no longer understates what is there: OAuth 2.0 lists the Password and Device Code grants added in 1.4.0, the per-request settings mention the proxy, and the scripting section gives the configurable timeout rather than only the 2-second default — and stops listing `require` as disabled two paragraphs after describing what it resolves.

## [1.5.0] - 2026-08-19

### Added
- **Response examples.** A saved response, paired with the request snapshot that produced it, kept with the request in the workspace. They document what an endpoint really returns, they are the fixture a test can be written against, and — because they live in the Git-backed YAML — changing one shows up as a reviewable diff, which is something a cloud-hosted example cannot offer. Capture one from the response panel or from a history entry, edit its status and body by hand, and reorder or rename the list from the request's new **Examples** tab. Each example is one file under `collections/<collection>/examples/<request>/`, with the response body in a sibling file named for its media type: a JSON body embedded in YAML is a block scalar no reviewer can read, and as its own `.json` file it diffs line by line. Capturing redacts in three layers — the exact values of secret environment variables, then the same key sweep the export paths use, then a warning for anything credential-shaped that survived — because a response body is the most likely place for a token to end up in a commit.
- **Examples arrive from every import path that carries them**, all of which discarded the data before: Postman's `item.response[]` (both directions), OpenAPI `responses` including a value derived from the response schema when the spec writes none, OpenCollection, and — the richest source, and the one nobody had noticed — **HAR**, which *is* a recording of request/response pairs and was being imported with the response half thrown away.
- **The Diff tab can compare against a saved example**, not just against the previous response. This is what keeps an example from quietly going stale: a response that no longer matches the contract shows up as a diff instead of passing unnoticed. The baseline is chosen per request, and falls back to the previous response if the example it pointed at is deleted.
- **A multipart part can carry its own Content-Type.** Every part went out as `application/octet-stream`, so an API that checks the MIME type of an upload rejected everything Kurlo sent. The value round-trips through Postman, Insomnia, OpenCollection and cURL's `;type=` suffix.
- **`kurlo --version` and `kurlo --diagnostics`.** Both are answered before the window opens, so they still work on a machine where it cannot — and the release now runs the binary it just built and checks the version it reports against the tag. A build whose `-ldflags` stamp did not land still calls itself `dev`, which would leave the updater unable to recognise any newer release.
- **Kurlo keeps a log, and the Support screen can hand it over.** The things worth knowing after something goes wrong — a credential store that could not be reached, a key that fell back to the recovery file — were written to a stdout that a packaged app throws away. They now go to `kurlo.log` in Kurlo's app-data directory, capped and rotated with one previous generation. **Settings → Support** gained **Copy diagnostics** (version, platform, Go, Git, storage mode and credential store — no workspace paths, so it can be pasted into a public issue) and **Open log folder**.

### Fixed
- **An explicit save wrote the previously saved version of the request.** In manual-save mode the store deliberately keeps the last saved version of a request that has unsaved edits — that is what stops a half-typed change reaching disk. But the dirty mark was cleared only after the write finished, so a save the user asked for was still counted as dirty while the file was being assembled: it wrote the *previous* version of the whole request, reported success, and cleared the unsaved indicator. The edit was gone on the next load with nothing saying so. Autosave was never affected.
- **AWS Signature v4 signed a fixed list of headers.** AWS requires every `x-amz-*` header to be part of the signature, so DynamoDB (`X-Amz-Target`), Lambda (`X-Amz-Invocation-Type`) and S3 with any of its option headers rejected every request with `SignatureDoesNotMatch`. The signed set is now taken from the request, canonical values are joined and whitespace-collapsed as the specification asks, and the signature covers the `Host` that is actually sent — overriding the header used to sign a name the server never sees. Signing also stopped reading the whole body into memory: past 32 MB, above every service that requires a signed payload, a large upload streams as `UNSIGNED-PAYLOAD` instead of being buffered whole.
- **A raw body type dropped its `Content-Type` when the text was empty.** Choosing JSON and sending nothing is a deliberate choice — the default body type is "none" — and the servers that validate the header before reading the body answered 415. `GET` and `HEAD` are left alone.
- **Digest auth with no username did nothing at all.** The challenge-response transport is only attached when there is a username, so the request went out unauthenticated and came back 401 with nothing to explain it. It is now an error before the request leaves, like AWS auth with no region.
- **`pm.sendRequest` ignored the request's proxy and client certificate.** It built its own blank transport, so a script logging in from behind a corporate proxy — or against an mTLS endpoint — could not reach it while the request beside it worked. It also returned a partially read body as if it were the whole response.
- **Send-and-Download saved the compressed stream.** Go only undoes gzip, and only when it set `Accept-Encoding` itself, so a request that asked for an encoding explicitly wrote a gzip file under a name like `report.json`. The body is decompressed on the way to the file now, falling back to the raw bytes when the stream is not what it claimed to be.
- **Importing a Postman collection dropped `protocolProfileBehavior` and path-variable values.** A collection that turns off redirects or certificate checking imported as one that does neither, and a URL kept `:id` with the value that fills it discarded — leaving a request that could not be sent. Kurlo has no per-request path variables, so those values are substituted into the URL.
- **The header actions moved when the view changed.** Save and Revert exist only for a request, so opening the runner unmounted them and the buttons that stay — runner, cookies, settings — slid sideways while a gap opened at the right edge. The searchbar's last grid track now takes the slack instead of being sized to its contents.
- OAuth 2.0 built a fresh HTTP transport for every token request and stranded its idle sockets, which a collection run against an OAuth-protected API did once per send.
- **A Git-backed workspace looked like an ordinary folder on a machine without Git.** Kurlo drives Git by running it, and the failure to find the binary was discarded — so `git rev-parse` failing because there is no Git was reported the same way as "this is not a repository". On a stock Windows machine, or a Mac whose Command Line Tools are missing, opening a repository you had cloned elsewhere offered to initialise a new one over the top of it, and every button that followed failed with a raw `exec` error. Kurlo now says which of the two it is, names the fix for that platform, and disables the Git-dependent actions instead of inviting a click that cannot work. A workspace still opens in local mode without Git.
- **An unsaved edit could follow you onto another branch.** A branch checkout refuses to run against local changes, but it read `gitStatus`, which describes the files on disk — an edit made within the autosave debounce is not there yet. So the check passed, Git swapped the files underneath, and the debounce then wrote the pre-checkout editor state into the branch that had just been checked out: an uncommitted change on a branch it was never made on. The same window sat in front of creating a branch, applying a stash, pushing, and resolving, continuing or aborting a merge. Every operation that touches the worktree now settles the editor first — saving the pending write, or dropping it where the operation is what restores the files — through one helper, so this cannot be forgotten one operation at a time.
- **The repository root was reported in Git's shape, not the platform's.** `git rev-parse --show-toplevel` answers with forward slashes everywhere, including Windows, where that path is not comparable to one built with `filepath`.

### Changed
- **CI runs the Go tests on macOS and Windows, not only Linux.** Kurlo ships all three, and the Go side is where the platforms differ — it shells out to Git, resolves paths, and talks to each OS credential store. None of that was exercised until a user hit it. Three tests that assert Kurlo refuses to follow a symbolic link now skip on a machine that cannot create one, rather than failing for a reason that is not about Kurlo.
- **`latest.json` is tested against the code that reads it.** The manifest is written by a Python script during the release and parsed by the Go updater on every installed copy, with nothing connecting the two: a drift in field names or platform keys would stop auto-update everywhere at once, silently, and the release that would fix it is the one those copies could no longer see. The test runs the real script over a fake release and decodes the result with the real parser — including looking up the running platform's own key, which the cross-platform matrix now exercises on each OS.
- **The fatal-error guard is covered by tests.** It is the one part of Kurlo that has to behave correctly at the moment everything else already has not, which is exactly when a bug in it would go unnoticed. The classification — ignored noise, an immediately fatal render loop, and the burst threshold — is now a pure function with tests around it.
- **E2E covers the Git panel and collection import**, next to the existing walkthrough; committing from the Git panel is checked to write the editor's pending edit first, which is the regression above.
- **Durable writes survive a locked destination on Windows.** Every saved file lands through a temporary copy renamed over the target, which is what makes the write atomic. Unix always allows that rename; Windows refuses it while any other handle holds the destination — an antivirus scanner, a backup agent, the search indexer — and reports "Access is denied", so a save that hit that instant simply failed. The rename now retries over a short window, which is exactly the case the cross-platform matrix surfaced on its first run.
- **Kurlo's `.gitignore` entries follow the file's own line ending.** Git checks a workspace out with CRLF on Windows by default, and the managed entries were appended with LF — leaving a file with two kinds of line ending, which reads as a whole-file change the next time anything normalises it.
- **gRPC import paths are compared in the platform's own shape.** A workspace written on macOS and opened on Windows carried forward slashes, so the proto file's own directory was passed to protoc twice.
- **Tests no longer write into the real Kurlo profile on Windows.** They redirected the config directory with the Unix variables only, while `os.UserConfigDir` reads `%AppData%` there — so the suite shared one profile across tests (surfacing as decryption failures) and would have overwritten a developer's own workspace.
- **A manual release checklist** covers what no test can reach: the real installers, the first launch, the update from the previous version, and the uninstall. See `docs/RELEASE-CHECKLIST.md`.

## [1.4.0] - 2026-08-13

### Added
- **Request history keeps the response.** An entry used to record only the status line, so there was no way back to what an endpoint actually returned — and the documentation had been promising otherwise. Opening an entry now restores the response into the viewer alongside the request, and a row's ••• menu has **View response** for looking without reopening. Bodies live in their own encrypted files under `history/` rather than in the request store, which is rewritten in full on every save; they are capped at 2 MB, a binary response keeps no body (those bytes do not survive the trip to the interface), and a file is deleted when its entry expires, is deleted, or history is cleared.
- **Variables can be built from other variables.** `baseUrl = {{scheme}}://{{host}}` now resolves, up to a depth of 20, with a circular chain left alone rather than looping.
- **`kurlo run` obtains its own OAuth 2.0 tokens.** Client credentials and password grants are fetched from the token endpoint; Authorization Code and Device Code fall back to the stored refresh token, which is how they are meant to be renewed unattended. One token is shared by every request in a run that uses the same configuration, and a grant that genuinely needs a browser stops the run with an explanation instead of sending unauthenticated.
- **Authorization tab for WebSocket and Socket.IO.** The sender always applied auth to the handshake; the tab to configure it was missing, so the only route to a protected socket was a hand-written header.
- **SSE reconnection and WebSocket keep-alive are configurable.** All three settings were implemented in Go and had no field in the frontend model, so they sat unreachable for two releases.
- **The `Host` header works.** It was grouped with the framing headers and dropped. It now travels through `Request.Host`, which changes the header without changing where the connection goes. The headers Kurlo still refuses to send are named in the response panel instead of disappearing silently.

### Fixed
- **Saving a workspace dropped auth fields.** The workspace writer kept a hand-maintained list of which auth fields belong to which type, and it had not been updated since 1.0. A request set to **Inherit Auth** lost the setting entirely and reverted to sending none; AWS session tokens, the Device Code and Password grants, client-authentication methods, and the private-key-JWT configuration — every OAuth field added in 1.2.0 — were discarded on every save. The YAML is the only copy, so what the writer dropped was gone.
- **Any pre-request script corrupted repeated headers and query parameters.** A script's view of them is a map, which cannot hold two rows sharing a key, and the whole map was merged back afterwards. `?id=1&id=2` went out as `?id=2&id=2` and a disabled row came back enabled — for any request running any script, including one that only logged. Only keys a script actually writes are merged now, following Postman's upsert; rows it never names are left exactly as written.
- **OAuth 2.0 tokens were never refreshed for a request that was not on screen.** The refresh read the editor's own fields, so a collection run against an OAuth-protected API started returning 401 the moment the token expired, and a request set to **Inherit Auth** never refreshed at all. It now resolves the auth the request will actually send and writes the new token back where it came from.
- **Importing an OpenAPI spec produced requests that could not be sent.** Path parameters became `{{userId}}` with nothing defining them, the server was pasted into every URL, and declared security schemes were dropped so every request came in as No Auth. The server is now a `{{baseUrl}}` collection variable, path parameters become collection variables seeded from the spec, and `securitySchemes` map onto the request's auth.
- **Generated code dropped Basic, Digest, OAuth 2.0 and AWS auth.** Only Bearer and API keys reached the snippet, so a copied request came back 401 with nothing to say credentials had been left out. Basic and OAuth 2.0 are emitted in every language; cURL gained `--digest` and `--aws-sigv4`; Digest and SigV4 elsewhere open with a comment explaining what to reach for, rather than looking complete. Copying a request as cURL from the sidebar also resolves `{{variables}}` now.
- **The client-certificate passphrase was committed in plain text.** It lives in request settings, which the secret sweep did not cover, so a literal value went into the workspace YAML verbatim. It now becomes a local secret placeholder like every other credential, along with the OAuth password-grant password, the private key, and the AWS session token.
- **Collection variables written by a script were lost** when the script then called `pm.execution.skipRequest()` or failed.
- **A parallel collection run ignored variables written by earlier iterations.** The environment was read once at the start rather than between iterations, so a token fetched in iteration 1 was invisible in iteration 2.
- **SSE requests offered a Scripts tab** that never ran anything — the SSE path does not execute pre-request or test scripts.
- **The realtime panel's tab strip wrapped onto two lines** and the status summary spilled underneath it on a narrow panel — reachable at the minimum window size with the sidebar widened.

### Changed
- The frontend no longer restates the Go structs. Wire types are derived from the generated Wails bindings, which removed 45 hand-written duplicate type definitions and a hand-maintained copy of every bound method signature. CI regenerates the bindings and fails if they differ from what is committed, and `make bindings` is the way to update them. Four of the defects above were the same failure — a hand-maintained copy falling behind — and this is what closes that class.
- Request history now describes what it stores accurately in the README and the privacy page; it previously claimed responses were kept when they were not.

## [1.3.0] - 2026-08-01

### Added
- **`pm.request.body` — scripts can read and rewrite the body that is sent.** The pre-request sandbox had no access to the body at all, so the single most common reason to write a pre-request script — generating a payload, or signing one with HMAC — was impossible. `pm.request.body.raw` is readable and writable, `.json()` parses it, `.update(value)` replaces it (objects are stringified), and `.mode` reports the body type. Tengo gets the same surface as `pm.request.body` / `pm.request.set_body()`. A body written onto a request that had none is still sent — Kurlo picks `json` or `text` from the content — while a binary file body is left alone, since the script never saw those bytes. Test scripts see the body that actually went out.
- **JSON Schema assertions.** `pm.response.to.have.jsonSchema(schema)` validates the response against a draft-07 subset, and reports each failure with its path (`/items/1: missing required property "sku"`). `pm.response.to.have.jsonBody(path, value)` checks a single dotted path. The validator is shared with the `tv4` global and `require("ajv")`, so collections written against either report the same failures.
- **`require()` for the libraries imported Postman scripts expect.** `lodash` (also as the `_` global), `ajv`, `tv4`, `uuid`, `crypto-js`, and `chai` resolve to Kurlo implementations covering the calls that appear in test scripts; `atob`/`btoa` are globals now too. Anything else — including an unsupported lodash member — fails with a message naming what was asked for, instead of a downstream `undefined is not a function`. The sandbox globals are no longer `var`-declared, so a script can open with `const _ = require("lodash")` or `const expect = require("chai").expect` without a parse error.
- **Bulk edit for key/value tables.** Params, headers, and both form body types switch between the table and a `key:value` text form, `//` disabling a line — Postman's format, so a block of headers pastes straight across. Descriptions, secret flags, and attached files stay with their key across a round trip.
- **Insertable script snippets.** The Scripts tab's reference row is now a snippet library: clicking one appends working code — set a variable, add a header, edit or sign the body, assert a status, check a JSON schema — to the script being edited. The list follows the active engine.

### Fixed
- **A collection's script timeout and `pm.sendRequest` permission were ignored.** Both settings were left out of the list of defaults a request inherits, so a collection that raised the script cap or opened up `pm.sendRequest` changed nothing — while the request's Settings tab displayed *"Applied from collection"* next to the value it was not applying. They inherit now, they can be set from **Collection settings → Settings** (alongside the client certificate, which the documentation promised but the interface never offered), and `kurlo run` reads both from the workspace instead of only from `--script-timeout` / `--allow-send-request`, so a run behaves in CI the way it does in the app. The inherited set is now checked against the settings model by a test, so the next setting cannot quietly go missing.
- **Scripts could not edit a form or urlencoded body.** Those two modes are sent from their fields, and `pm.request.body.raw` writes went nowhere — no error, no log, just a request that ignored the script. `pm.request.body.urlencoded` and `pm.request.body.formdata` now expose Postman's field list (`add`, `upsert`, `remove`, `each`, `toObject`, …), a file field keeps its attachment when a script rewrites its value, and a raw write on a form body is reported in the script log instead of vanishing. `pm.request.body.update({ mode, urlencoded })` replaces every field at once. A **binary** request with no file chosen also keeps a body the script builds, rather than sending nothing.
- **`pm.request.body.mode` reported Kurlo's names, not Postman's.** It returned `json`, `text`, or `form`, so an imported `if (pm.request.body.mode === "raw")` never matched and the script took the wrong branch in silence. Every text body is `raw` now, form-data is `formdata`, a file body is `file` — Postman's vocabulary throughout.
- **A JSON Schema failure list stopped at 20 without saying so.** A response far off its schema reported exactly twenty problems as though they were all of them; the report now ends with how many more there were.
- **Importing a Postman collection dropped every script.** The importer never read `item.event`, so pre-request and test scripts — often the reason the collection exists — were silently discarded, and even a Kurlo → Postman → Kurlo round trip lost them. Scripts now import, along with request descriptions (which become the request's Docs tab). Folder-level scripts, which have no equivalent layer in Kurlo, are copied into each request the folder contains and labelled with their origin.
- **Importing a Postman collection dropped everything defined on the collection itself.** Collection variables, collection auth, and the collection's pre-request/test scripts were ignored; only `item` and the top-level `auth` were read. They now land in the collection's defaults, which is where Kurlo applies them for every request. A request that declared no auth of its own is marked **Inherit Auth** rather than getting a copy, so changing the collection's auth after the import works. Folders that hold no requests are preserved.
- **Postman OAuth 2.0 imports kept only the access token.** The grant type, authorization and token URLs, client id and secret, scope, audience, refresh token, and client authentication method were all discarded, so an imported request started failing with a 401 as soon as the stored token expired. The whole configuration now carries over. AWS SigV4 session tokens import too.
- **Postman environment and globals files could not be imported.** They export as separate JSON files that look nothing like a collection, so the import failed with "Expected a Postman collection JSON file" — leaving every `{{variable}}` in the freshly imported collection unresolved. The Postman importer now recognises them and imports an environment (made active) or merges into Globals, preserving secret flags.
- **Postman exports put `event` in the wrong place.** Scripts were written under `request.event`; the v2.1 schema hangs `event` off the item, which is where Postman looks. Exports also now carry the collection's variables, auth, and scripts, plus each request's documentation.

## [1.2.0] - 2026-07-26

### Added
- **Digest auth beyond MD5.** `SHA-256`, `SHA-512-256`, and the `-sess` session variants from RFC 7616, plus `qop=auth-int` and `userhash`. Previously any algorithm other than MD5 was rejected outright, so a modern Digest server failed before the request went out. When a server offers both `auth` and `auth-int`, plain `auth` is used so the body never has to be buffered.
- **Two more OAuth 2.0 grants.** **Device Code** (RFC 8628) shows the user code, opens the verification page, and polls the token endpoint — honouring the server's `interval` and backing off on `slow_down` — for machines where a loopback redirect cannot work. **Password** covers the RFC 6749 resource-owner grant.
- **Client authentication methods for OAuth 2.0.** Alongside HTTP Basic, the token endpoint can now be given `client_secret_post`, **client secret JWT** (HS256), or **private key JWT** (RSA/ECDSA, RFC 7523). The private key accepts a `{{variable}}` so it can live in workspace secrets. An `audience` parameter is also sent when set, which Auth0 and others require.
- **Scripting: `pm.sendRequest`.** Scripts can make their own HTTP calls — fetching a token before the send, or chaining setup — in both Postman's callback form and as a direct return value. It is off by default and enabled per request (**Allow pm.sendRequest** in Settings) or with `kurlo run --allow-send-request`; the sandbox otherwise stays network-free. The call carries its own 30 s timeout, 8 MB response cap and 5-redirect limit, and deliberately does not inherit the parent request's auth, client certificate, or cookie jar.
- **Scripting: the missing variable scopes.** `pm.collectionVariables` reads and writes the collection scope, and a write is saved back onto the collection after the send. `pm.globals` is available as an alias for the session scope. `pm.variables.get` now resolves across every scope in Postman's precedence order (data row → environment → collection → session) instead of only the session one.
- **Scripting: `pm.crypto` and a `CryptoJS` shim.** MD5/SHA-1/SHA-2 digests, HMAC, base64, random hex, and UUIDs, in hex, base64, or base64url. The `CryptoJS` global covers the digest and encoding calls that appear in real Postman collections, so imported request-signing scripts work unchanged.
- **Scripting: `pm.info`, `pm.cookies`, and `pm.execution.skipRequest()`.** `pm.info` exposes the request name, event name, and iteration counters; `pm.cookies` gives read-only access to the cookies the request would send; `skipRequest()` skips the send from a pre-request script and is reported as a skip rather than a failure, so a conditional request does not fail a run or a CI exit code.
- **Configurable script timeout.** The 2 s cap is now a per-request setting (**Script timeout**) and a `kurlo run --script-timeout` flag, with a 60 s ceiling so a runaway loop still cannot wedge a send or a CI job. Heavy assertion suites and signing steps no longer fail for want of time.
- **AWS Signature v4: session tokens.** Temporary credentials from STS, an assumed role, or AWS SSO now work: the token goes out as `x-amz-security-token` and is folded into `SignedHeaders`. Sending it without signing it is exactly what AWS rejects, so the signature changes accordingly.
- **A Preview tab in the response viewer.** Images render on a checkerboard with their dimensions, and an image response opens on the tab automatically — the text view only ever showed their bytes as mojibake. HTML renders in a fully sandboxed frame with scripts and network access blocked, so a page from any server is safe to look at. Images reach the viewer through their own lossless channel, because the response body crosses to the interface as text and binary would not survive the trip.
- **Global variables have a home.** They persist across restarts, are shared by every workspace, and are edited under **Environments → Globals**. Previously the scope `pm.globals` and `pm.variables.set` write to existed only in memory, with no way to see it and nothing left after a restart. A value a script writes now shows up in the editor after the send, and is saved.

### Fixed
- **`kurlo run` could not run a collection that used inherited auth.** A request set to **Inherit Auth** — the pattern the documentation recommends for a collection that talks to one API — aborted with `auth error: unsupported auth type "inherit"`. The CLI read only `defaults.variables` from a collection and ignored its auth, headers, scripts, and settings, so a workspace that worked in the app was unrunnable in CI. The runner now resolves collection defaults with the same rules the app uses.
- **A binary response no longer fills the Body tab with replacement characters.** Kurlo now detects a non-text body from the actual bytes and shows what it is (sniffed type and size) with a link to the preview and a save action, instead of rendering mojibake. Detection is byte-based, so a server that mislabels binary as `text/html` is handled too — and such a response no longer offers a broken HTML preview.

### Changed
- Collection variables are no longer folded into the session variable pool while a script runs. They live in their own scope, which is what lets `pm.collectionVariables` address them distinctly and removes an ambiguity where a collection variable could not be told apart from a session variable holding the same value.

## [1.1.0] - 2026-07-24

### Added
- Client certificates (mutual TLS): a request setting for a certificate, an optional separate key, and a passphrase (which accepts a `{{variable}}` so it can live in workspace secrets). Set it on a collection to reuse across requests. A bad path or wrong passphrase fails before dialing with a clear message.
- `kurlo run` — a CLI runner for CI and the terminal. It executes a YAML workspace's HTTP and GraphQL requests and their JavaScript test scripts, resolving environment, collection, global, and dynamic variables (the full dynamic set, matching the app), and reports as `cli`, `json`, or `junit`. Exit code is non-zero when any request errors or any assertion fails. Variables a test writes (`pm.environment.set`) carry into later requests in the run. Realtime request types are skipped.
  - **Data-driven runs** (`--data <file.csv|json>`): one iteration per row, columns exposed as variables and via `pm.iterationData.get()`.
  - **Multiple reporters** (`--reporters cli,json,junit`) with file export (`--reporter-json-export`, `--reporter-junit-export`).
  - **Variable scopes**: `--globals`/`--global-var`, and `--export-environment`/`--export-globals` (Postman-compatible) to write final values back after a run.
  - **`--verbose`** per-request request/response detail, **`--insecure`/`-k`**, **`--bail`**, and a failure list plus average-response-time and data-received totals in the summary.
- Scripting: `pm.iterationData.get(key)` reads the current data-file row (read-only) in both the app's Collection Runner and `kurlo run`.
- Dynamic variables: `{{$guid}}`, `{{$timestamp}}`, `{{$randomEmail}}` and around 50 more, generated at send time under Postman's names. Imported Postman collections that used them no longer fail with "unresolved variable". An environment value with the same name still wins.
- Import for `.http` / `.rest` files from the JetBrains HTTP Client and the VS Code REST Client, including `###` separators, `# @name` directives, and file variables (which become collection variables).
- Response **Timeline** tab: DNS, TCP, TLS and first-byte events on a millisecond scale; connection details (reused or new, addresses, TLS version, cipher, ALPN, SNI); and the request line and headers exactly as they went on the wire, one block per redirect hop. Secret values are masked. Failed requests keep their timeline.
- Response **Diff** tab comparing the current response body with the previous one for the same request, with collapsed unchanged runs.

### Changed
- Wails updated to 2.13, along with the Go dependency set (`golang.org/x/net`, `golang.org/x/crypto`, gRPC, minisign) and the frontend toolchain (Svelte 5.56, TypeScript 7, Vite plugin 6). No behaviour change is intended; the desktop app is otherwise identical to 1.0.0.
- Parallel collection runs take a **Max concurrent requests** setting (default 8, maximum 64).

### Fixed
- Query parameters kept their order on the wire. They were sorted alphabetically whenever automatic URL encoding was on (the default), which broke APIs that sign the query string verbatim. A bare `?flag` also survives instead of becoming `?flag=`.
- HTTP connections are reused between requests. Every send built its own transport, so each one paid a fresh TCP and TLS handshake, reported connect timings that never reflected a warm connection, and left its idle sockets behind until they timed out — a long collection run stranded one transport per request.
- A parallel collection run no longer fires the entire batch at once. A large collection opened one socket per request simultaneously, which could exhaust file descriptors and produce failures unrelated to the API under test.
- Documentation site: the theme toggle changed only its own label because the brand palette was applied to both themes. Light mode works again.
- Documentation site: hand-written links dropped the deploy base path and returned 404s.
- Release automation: release notes fell back to a placeholder instead of reading the annotated tag message.

## [1.0.0] - 2026-07-21

First public release. Kurlo had been developed privately up to this point; the
source is now open under the MIT license and every release is published from
this repository.

### Requests
- All HTTP methods, with query params, headers, and body editors (JSON, form-data, x-www-form-urlencoded, raw text/XML/HTML, binary file).
- GraphQL, Server-Sent Events, WebSocket, Socket.IO, and gRPC request types, each with a dedicated realtime panel.
- SSE streams reconnect like a browser `EventSource`: `Last-Event-ID` resume, server-provided `retry:` interval, and no loss of already-received events.
- cURL import by pasting a command into the URL field.
- Importers for Postman, Insomnia, Bruno/OpenCollection, OpenAPI/Swagger, HAR, cURL, and full-backup archives; exporters for Postman, OpenAPI, OpenCollection, and full backups.

### Authentication
- Bearer, Basic, Digest (full MD5 challenge-response), and API Key (header or query) schemes.
- OAuth 2.0 Client Credentials and Authorization Code with PKCE — loopback browser sign-in per RFC 8252, S256 for public clients, HTTP Basic for confidential ones, stored refresh tokens, and automatic refresh immediately before a request is sent.
- AWS Signature v4, with query-string canonicalization per the signing specification.
- Auth defaults inherited from collection and folder level.

### Scripting
- Sandboxed JavaScript pre-request and test scripts with a `pm.*` API, plus the legacy Tengo engine for existing requests. Imports, filesystem, process, and network access are disabled; execution is capped at 2 seconds.

### Workspaces
- Multiple workspaces, nested collections, drag-and-drop organization, and 14-day request history.
- Git-backed YAML workspaces with diagnostics, conflict helpers, and secrets that never leave the machine.
- Local profile and secrets encrypted at rest with AES-256-GCM; the key lives in the OS credential store when one is available, with a `0600` recovery file as a fallback.

### Response viewer
- Syntax highlighting, line numbers, full-text search with match navigation, headers table, test results, and script logs in a single panel.
- Paginated rendering for large bodies (512 KB pages past a 10 MB threshold) with accurate truncation reporting.
- Save to file and copy to clipboard, including a Send-and-Download path that writes binary responses byte-exact.

### Updates
- Signed auto-updates: `latest.json` is read from release assets rather than the GitHub API, and every downloaded binary must match both the manifest SHA-256 and a minisign signature before it is installed.

### Interface
- Dark and light themes with several built-in variations.
- Configurable keyboard shortcuts throughout, global search (`⌘K`), quick send (`⌘Enter`), and tab switching (`⌘1`–`⌘9`).
- Settings search and full keyboard navigation, theme previews, and onboarding empty states.
